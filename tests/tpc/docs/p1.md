# Member C: arrays-of-pointers P1

P1 is a `TPCComponent`, source **2**, destination **L1D (1)**. It learns the
signed difference between a producer's returned pointer and a dependent load's
virtual address after four consistent observations from distinct producer
instances. It uses the shared translating transport and accounting. The second
stage is a dependent memory access, not an L2 destination.

**Real T2 is still absent.** Experimental T/TP/TPC factories continue to reject
missing T2. `P1ProducerFixture` exists only with `TPC_TESTS=1`; it is a fixed
lookahead stimulus for tests, not a T2 implementation or performance profile.
Neither this work nor fixture results establish full TP/TPC performance.

## CPU and relation identity

`BaseO3CPU.p1_controller` connects retirement to the controller. Successful
ordinary x86 `ld` completions retain actual packet bytes on the DynInst; this
covers the shared LSQ completion path for cache hits, misses, forwarding and
assembled split responses. Values are little-endian and producers are 8 bytes.
Failed/faulted loads cannot seed provenance. No functional memory read is used.

At retirement, the controller provides P1 a capability stamped with the
committed dependent instruction's request. Integer-register provenance records
carry the **producer sequence number, returned value, stream slot/version,
context, PC/micro-PC and I-cache residency**. Architectural register tracking is
valid here because retirement is in program order: overwriting a destination
replaces or clears its token. This supports simultaneous dynamic instances held
in different registers, rather than matching the most recent value at a PC.
Only the x86 load's actual base/index operands participate in address dependency;
the old destination used for partial-register merging does not. Unconditional
register moves filter unused old-destination operands; full-width self-XOR
clears provenance. Partial moves retain their contributing old-register source.

Non-memory integer dataflow propagates one unambiguous producer token; mixed
producer instances are conservatively discarded. Memory does not propagate taint
through spills/reloads. Unsupported load forms clear their destination tokens.
This is a deliberately conservative register-dataflow approximation, not exact
bit-level dynamic slicing. Conditional/arithmetic operations can over-taint;
constant-offset training is an additional filter, not a proof of semantics.

This differs from paper IV-B's decode-time taint circuit: training and demand
value prediction occur at retirement, later than execution. Branch squashes and
replays cannot contribute uncommitted observations. Architectural traps and
syscalls, thread removal and CPU switch/takeover reset streams, registers,
relations and deferred work. Branch misprediction and memory-order recovery
also conservatively reset P1: future T2 producer requests may have speculative
triggers even though P1 training is committed. This sacrifices training history
to avoid retaining obsolete speculative handoffs.
Micro-ops use separate micro-PC identities while sharing the existing start-byte
I-cache classification location. No speculative training rollback is needed.

## Member B integration contract

The types live in `gem5/src/mem/cache/prefetch/p1_events.hh`. T2 owns its producer
stream, producer prediction/distance and replacement policy:

1. During T2's authorized `onPredict`, call `announcePointerStream(stream)`.
   T2 also receives committed operations before P1 through `onRetiredOperation`;
   it may announce a recognized successful load there, which supports streams
   whose loads bypass the cache via forwarding. This observation callback gets
   no candidate-submission capability.
   Include nonzero monotonically changing `version` for every reuse of `slot`,
   exact producer PC/micro-PC, context and original `InstructionSource`.
   LSQ requests carry `LoadIdentity` with sequence and micro-PC, including split
   fragments. Do not derive instruction physical addresses from data addresses.
2. Compute producer lookahead as `baseDistance * pointerDistanceMultiplier(stream)`.
   The result is **1 or 2**, not an instruction to multiply the previous distance.
   Repeated recognition therefore cannot double distance exponentially. The
   multiplier is 2 while a confident relation exists; it resets on loss of the
   relation/stream. T2 alone emits producer candidates, source 1, through common
   transport. Ordinary controller ownership still stops at T2.
3. Before submitting a future producer, call `requestPointerValue({stream, req})`
   with its exact **8-byte translated Request**, including VA, PA, context and
   security. Subscribe even when the common queue will filter a cache hit or
   pending miss. Translation must be real and context-correct; no guessed PA.
   A deferred T2 translation callback may subscribe while idle, but only for an
   already registered live stream. P1 rejects unknown/replaced stream identities;
   this does not grant T2 a P1 submission capability. T2 can use its own saved
   capability to submit the translated producer through common transport.
   The hierarchy hook also registers the CPU MMU with T2. Its inherited `mmu`
   and constructor `p.sys->threads[context]` support a real `translateTiming`
   request; T2 must bound/cancel these translation callbacks. After translation,
   subscribe the exact 8-byte request and submit the producer PA with the saved
   T2 capability, avoiding a second translation. No functional translation/read
   shortcut is part of this contract.
4. Call `cancelPointerStream(oldIdentity)` on replacement/reset. Announcing a
   different version of the same slot also cancels its old relations/work.
   The controller broadcasts `RetiredOperation.reset` to all components on CPU
   recovery; T2 must invalidate its stream versions and cancel outstanding
   translation callbacks then. A delayed callback must retain its original
   version, never relabel old work with a replacement stream identity.

The controller dispatches committed CPU events independently of cache ownership
and creates **P1-owned** capabilities. P1 cannot borrow T2's capability or bypass
source/target/residency/throttle checks. Relation capabilities refer to the
learned dependent instruction, not the producer.

For a resident producer, P1 snapshots the actual readable L1D line and waits until
`max(now, block.whenReady) + tagLatency + dataLatency + computationLatency`.
This adds conservative array-access latency but **does not model extra cache
ports or contention**. For a pending/missing producer, the subscription waits for
a matching L1 fill; the new `FillEvent.secure/ready` fields carry security and
block data readiness, including header/payload/fill delay. Prediction waits an
additional cycle. There is no assumption that packet arrival equals data ready.
Several exact pointer offsets and several relations can subscribe to one line;
the fill's single accounting origin is not used as a consumer identity.

Future split producer reads are explicitly rejected, because one contiguous PA
cannot describe two translated pages. Demand splits use the LSQ assembled value.
B must not subscribe separately to split fragments. An uncacheable producer,
non-8-byte producer, missing translation/context or straddling line returns no
prediction. There is no retry or functional fallback; missing returns expire.

Dependent targets use checked signed addition, reject null pointers, overflow,
and non-user/canonical 48-bit addresses, then submit **virtual** candidates to
the existing MMU-backed L1 route. Page crossings are translated normally; no
physical-stride inference is applied to returned pointers.

## Bounds, lifetimes and statistics

Defaults are 32 stream subscriptions, eight relation slots, 256 architectural
integer token slots, 32 pending value consumers, and a 1us timeout. Full stream
storage replaces the oldest registration; full relation storage replaces the
oldest relation version; full value storage rejects new work. Relation epochs
change on replacement/offset mismatch, and every deferred consumer checks its
saved epoch and both instruction residencies before submission. Invalidation
synchronously cancels associated work. P1 writes only the independent P1 two-bit
namespace (unknown/training/confident); C1/T2 state and public accounting remain
separate. Internal `p1.*` diagnostics count training/value work; public generated,
accepted, useful, late, dropped and unresolved events remain framework-owned.

The arrays and metadata are simulator storage, not a reproduction of Table II's
1.07 KiB P1 area estimate. Self-dependent linked-list traversal, pointer-width
variants, vector/atomic loads, hardware transactions (which reset P1), SMT, address-space reuse/exec/JIT, hot-state
checkpoint serialization and full memory taint are outside the supported scope.

## Reproduction

Run these commands from the **gem5 repository root**. The fixture imports the
unchanged parent project's `configs/system.py` to preserve the frozen hardware;
no parent config, benchmark, README, gitlink or PR changes are required.
`TPCController.bindHierarchy` discovers the O3 owner of the supplied I-cache and
binds `p1_controller` when source 2 is present.

```bash
# An existing Python 3.10-3.12 environment with SCons is sufficient. In this
# worktree the prepared environment is build/p1-venv (Python 3.11.18).
TPC_TESTS=1 JOBS=2 tests/tpc/build-p1.sh PROTOCOL=None USE_SYSTEMC=0
(cd .. && gem5/build/p1-venv/bin/python -m unittest discover -s benchmarks -p 'test_*.py')
build/p1-venv/bin/python -m unittest discover -s tests/tpc -p 'test_pointer.py'
g++ -std=c++17 -Isrc tests/tpc/p1_math.cc -o build/p1-math-test
build/p1-math-test
# Directed controller/return tests plus all seven native/simulated guest modes:
build/p1-venv/bin/python tests/tpc/validate_p1.py
# Outputs: build/p1-validation/{report.json,directed.log,MODE.log,MODE/,...}
# Normal production build, excluding opt-in test SimObjects:
JOBS=2 tests/tpc/build-p1.sh PROTOCOL=None USE_SYSTEMC=0
```

The helper accepts `P1_PYTHON=/absolute/path/to/python` to use another supported
environment. It selects that interpreter's `python3-config` and library path.
Ruby and SystemC are disabled only as build options; the frozen Classic Cache
simulation is unchanged. `validate_p1.py` supplies the shared-library path when
launching gem5. For manual runs, export `LD_LIBRARY_PATH` to the Python base
prefix's `lib` directory if needed.

Manual guest/config invocation:

```bash
mkdir -p build/p1-validation
gcc -O2 -static -fno-pie -no-pie tests/tpc/pointer.c -o build/p1-validation/pointer
nm build/p1-validation/pointer | rg 'p1_(producer|dependent)'
# Substitute the actual p1_producer symbol address for PRODUCER_PC.
build/X86/gem5.fast -d build/p1-positive tests/tpc/p1.py build/p1-validation/pointer PRODUCER_PC positive
# The directed fixture uses a synthetic PC, deliberately independent of nm:
build/X86/gem5.fast -d build/p1-directed tests/tpc/p1.py build/p1-validation/pointer 0x400007 --directed
```

The `split` guest puts the pointer array at byte offset 60 of a cache line,
including virtual-page crossings; `forwarded` stores the exact producer slot
immediately before loading it. Both retain explicit producer/dependent symbols.
Native tests cover positive, negative, zero, varying, independent, split and
forwarded modes. The runtime driver additionally requires buffered producer
completion evidence for split/forwarded cases. Real T2 is still absent.
